# MHGU Monster Info

A monster reference for **Monster Hunter Generations Ultimate**. Version one
is hitzone heat maps: every monster's per-part damage values (cut, impact,
shot, the five elements, KO and exhaust), colour-coded so the weak points
jump out — including the parallel tables the game holds for some monsters
(enraged / broken states, not yet labelled).

Live: https://armoredraven17.github.io/MHGU-Monster-Info/

More monster info (stagger limits, drops, and the like) is planned; the
detail pane is built as independent sections so new ones can slot in.

## How it fits the family

Static site served from `docs/`, no build step, deployed to GitHub Pages on
push to `master`. Styled to match the other MHGU apps by the same author —
see the links dialog in the app.

## Data

The hitzone tables under `docs/data/` are generated by
`scripts/build-data.mjs` (Node ≥ 18, no dependencies) from
`data-src/hitzones_v3.json`, which was decoded from the game's own RomFS
`dt_tune` files (personally-owned cartridge — see [NOTICE.md](NOTICE.md)).
Nothing under `docs/data/` is edited by hand.

```
node scripts/build-data.mjs
```

Two honesty rules carried through from the extraction:

- **Parallel tables are unlabelled.** Where the game stores more than one
  hitzone table for a monster, the app shows them as "Table 1 / Table 2"
  rather than guessing which is enraged or broken. Labels will be added as
  they're verified.
- **Part names only where verified.** Names were assigned only where the
  extracted table byte-matched a known ordering; everywhere else parts show
  a numbered label until verified.

## Local development

```
python -m http.server 8129 --directory docs
```

Data ships as a `window` global, so `file://` also works — but serve over
HTTP for parity with the deployed site.

## Cache busting

GitHub Pages caches aggressively by full URL. Every `<link>`/`<script>` in
`index.html` carries a `?v=N` query — bump the number whenever the file it
points at changes, or browsers will run stale code.
